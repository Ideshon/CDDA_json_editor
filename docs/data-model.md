# Модель Данных

## ModProject

`ModProject` хранит состояние открытого мода:

- `root` - корень открытого мода или папка одиночного JSON-файла.
- `files` - соответствие `Path -> list[dict]` для загруженных JSON-файлов.
- `objects_by_schema` - объекты, сгруппированные по ключу схемы.
- `ids_by_type` - зарегистрированные id по JSON `type`.
- `dirty_files` - файлы, которые нужно сохранить.
- `load_warnings` - предупреждения загрузки JSON.
- `current_backup` - последний бэкап, созданный при открытии мода или отдельного JSON-файла.

## ModObject

`ModObject` связывает JSON-словарь с метаданными:

- `schema_key`;
- `json_type`;
- `file_path`;
- `data`.

Объект не копирует JSON-данные. Он держит ссылку на словарь внутри `ModProject.files`, поэтому изменения редактора сразу применяются к данным проекта и сохраняются через `ModProject`.

## Индексы

`ModProject` ведет:

- индекс объектов по `json_type/id`;
- индекс объектов по файлам;
- исходящие ссылки объекта по полям схемы с типом `ref_list`;
- входящие ссылки на объект по тем же найденным связям.

Эти индексы нужны для перемещения, переименования и окна связей. Текущая версия индексирует только ссылки, описанные в схемах как `ref_list`; более глубокие JSON-ссылки будут добавляться отдельными итерациями.

Окно связей использует эти индексы без повторного сканирования JSON: входящие строки строятся через `incoming_references_for(obj)`, исходящие строки через `outgoing_references_for(obj)`. Если исходящая ссылка указывает на id, которого нет в загруженном проекте, строка остается видимой как не найденная цель.

## Снимки И Undo/Redo

`ProjectEditState` хранит снимок редактируемой части проекта:

- `root`;
- глубокую копию `files`;
- набор `dirty_files`.

`ModProject.capture_edit_state()` создает снимок перед действием, а `ModProject.restore_edit_state(state)` восстанавливает `files`, `dirty_files`, объекты и индексы из снимка. `ProjectActionHistory` хранит пары снимков `before/after` и используется главным окном для отмены и повтора действий редактора.

Текущий undo/redo охватывает изменения в памяти: создание, удаление, перемещение, переименование объектов, добавление/удаление полей и применение изменений полей редактора. Открытие нового проекта и восстановление из бэкапа очищают историю действий.

## Перемещение Объектов

`ModProject.move_objects_to_file(objects, target_path)`:

- удаляет JSON-словарь объекта из старого списка файла;
- добавляет тот же словарь в список целевого файла;
- обновляет `ModObject.file_path`;
- помечает старый и новый файл dirty;
- перестраивает индексы после перемещения;
- создает папку целевого файла при сохранении, если ее еще нет.

## Переименование Объектов

`ModProject.rename_object(obj, new_id, update_references)`:

- меняет id-поле объекта согласно его схеме;
- запрещает пустой id;
- запрещает дубликат `json_type/id`;
- помечает файл объекта dirty;
- при `update_references=True` обновляет найденные входящие ссылки в полях `ref_list`;
- помечает файлы объектов-источников dirty, если их ссылки изменились;
- перестраивает `ids_by_type`, индекс объектов и индекс связей.

Текущая версия обновляет только ссылки, которые уже распознаются индексом связей: schema-defined `ref_list`.

## Бэкапы

`BackupInfo` описывает последний созданный бэкап:

- `source_path` - исходная папка мода или отдельный JSON-файл;
- `backup_path` - папка снимка внутри `.cdda_mod_editor_backups`;
- `kind` - `directory` или `file`;
- `created_at_utc` - время создания в UTC.

`ModProject.create_open_backup(source_path)` создает снимок перед загрузкой проекта. Для папки мода бэкап хранится рядом с открытой папкой, а не внутри нее. Для одиночного JSON-файла создается папка снимка с копией этого файла. Папки `.cdda_mod_editor_backups` исключаются из загрузки JSON, чтобы бэкапы не попадали в дерево объектов.

`ModProject.create_autobackup()` создает снимок из текущего состояния `ModProject.files`. Он записывает несохраненные изменения в папку бэкапа, но не перезаписывает рабочие JSON-файлы мода и не очищает `dirty_files`.

`ModProject.restore_current_backup()` заменяет текущие файлы содержимым последнего бэкапа и заново загружает проект. В UI восстановление требует подтверждения, потому что текущие файлы будут заменены. Если во время работы уже создавались автобэкапы, восстановление использует последний созданный автобэкап.
